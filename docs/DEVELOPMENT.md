# 📱 Legion Multi-Bot (Standalone Client)

Отдельное приложение для запуска мультибоксинга и изолированных окон браузера с индивидуальными VPN-прокси.

## 🚀 Запуск программы:
- **`Запустить_Мультибот.bat`** — запускает главное графическое окно мульти-боксера (сетка 6x2 смартфонов, управление окнами, VPN-диспетчер).
- При каждом запуске главного окна выберите **«С VPN»** или **«Без VPN»**. В режиме «Без VPN» одиночный запуск, запуск страницы, всех ботов и авторизация используют прямое подключение; Xray, проверки VPN и настройка прокси не запускаются. Chrome получает `--no-proxy-server`, чтобы не наследовать системный прокси. Системный VPN нужно отключать отдельно. Для смены режима перезапустите программу. Закрытие окна выбора отменяет запуск.
- **`Запустить_Менеджер_Профилей.bat`** — запускает локальный веб-менеджер и открывает его в Chrome. Порт выбирается автоматически; адрес также выводится в консоль.

При закрытии главного окна или графического менеджера закрываются принадлежащие ему браузеры, локальные VPN-прокси и Xray. При принудительном завершении процесса Windows освобождает его группы процессов и завершает Chrome и Xray. Личный Chrome и сторонние VPN-клиенты не закрываются. Веб-менеджер, запущенный через BAT, завершает сервер и свои компоненты через две секунды после закрытия последней вкладки менеджера; обновление страницы и другие открытые вкладки сохраняют его работу. Закрытие консоли также завершает его Python-компонент и ботов. При быстром запуске всех ботов консоль остаётся открытой до закрытия последнего браузера; закрытие этой консоли останавливает запущенных ею ботов.

При запуске главного окна и графического менеджера приложение в фоне проверяет стабильные релизы [Daniil0414/LegionMultiBot](https://github.com/Daniil0414/LegionMultiBot/releases). Если вышла новая версия, появляется окно с текущей и новой версиями, описанием изменений и кнопками **«Обновить и перезапустить»** и **«Не обновлять»**. Отказ действует до следующего запуска. Без интернета приложение продолжает обычную работу.

После согласия архив скачивается с отображением прогресса; скачивание можно отменить кнопкой «Не обновлять». Перед установкой приложение закрывает свои игровые окна, установщик дожидается завершения процесса и перезапускает приложение. Аккаунты, настройки, VPN-ключи, скрипты и профили браузера сохраняются. При ошибке замены файлов восстанавливается предыдущая версия; при невозможности отката установщик сообщает путь к резервной копии. Windows-сборка использует `LegionMultiBot-windows.zip` и проверяет SHA-256, предоставленный GitHub. Запуск из исходников использует `legion-multibot.zip` с проверкой SHA-256 либо исходники соответствующего тега по HTTPS.

Для выпуска обновления увеличьте `APP_VERSION` в `app_version.py`, создайте соответствующий тег `vX.Y.Z` и опубликуйте стабильный GitHub Release с файлами этой версии. Для исходников можно приложить архив `dist/legion-multibot.zip`, полученный командой `python -B package_app.py`. Полная Windows-сборка создаётся через `python -B .github/build_portable.py --cache dist/portable-cache --output dist/release`: в неё входят приложение и встроенные компоненты. Черновики, предварительные релизы, текущая и более старые версии не устанавливаются.

## 🛡️ Безопасность и изоляция:

В режиме «С VPN» откройте **«Настройки VPN» → «JSON серверов по ссылке подписки»**, вставьте ссылку и нажмите **«Получить JSON по ссылке»**. Happ не требуется, не открывается и не используется как прокси: программа сама запрашивает провайдера и преобразует список ключей, Base64 или JSON в JSON-конфигурации отдельных серверов. Из полных конфигураций извлекаются все поддерживаемые прокси-outbound, а не только первый; прямые и блокирующие маршруты не включаются. Для подписок с привязкой устройства передаётся существующий `MachineGuid` Windows как HWID; случайный ID не создаётся, данные других устройств не используются. Провайдер может отказать в доступе или сообщить о лимите устройств; такие ответы не заменяют рабочие серверы.

Получение JSON работает и при открытых ботах и не изменяет текущие VPN-маршруты. Чтобы сохранить серверы и ссылку в `.vpn_runtime/vpn_config.json`, закройте окна ботов и нажмите зелёную **«Применить и закрыть»**: окно закроется после успешного применения, а при ошибке останется открытым. Синяя **«Не применять и закрыть»** закрывает настройки без применения; полученный текст и ссылка сохраняются в памяти до завершения программы. Кнопка **«Получить JSON из открытого Happ»** оставлена для необязательного импорта из уже работающего клиента. Для получения JSON по ссылке достаточно Python, установка Happ и Xray не нужна. Для запуска браузеров через VPN нужен Xray: поддерживается отдельный `xray.exe` рядом с программой или в `../bin`, а также ядро установленного Happ.

Описанные ниже проверки VPN и изоляции внешних IP действуют в режиме «С VPN». В режиме «Без VPN» отдельные каталоги профилей сохраняются, но разные внешние IP не проверяются и не требуются. Остальные запускатели продолжают работать через VPN.
- **Обычный Chrome в сетке**: экран, DPR, указатель, сенсорные возможности, ориентация, User-Agent и Client Hints остаются штатными. Эмуляция телефона по умолчанию отключена; сетка изменяет размеры настоящих окон. Лаунчер не подменяет WebGL/Canvas/Audio или браузерные JavaScript-функции.
- **Мульти-прокси (Xray Core)**: перед запуском выбирается рабочий VPN-сервер с учётом стартовой проверки. Если он не отвечает или его внешний IP закреплён за другим профилем, проверяется следующий сервер из пула. Браузер подключается к постоянному локальному SOCKS-прокси своего аккаунта; за ним можно заменить VPN-сервер без перезапуска Chrome.
- **Автоматический резерв VPN**: в фоне подбирается и проверяется отдельный резервный сервер с IP, не закреплённым за другим профилем. Основной и резервный каналы проверяются параллельно; интервал между проверками — 2 секунды, тайм-аут каждой из двух HTTPS-проверок — 2 секунды. При отказе SOCKS-подключения готовый резерв используется сразу в том же запросе; обрыв после установки туннеля обнаруживается проверками. Старые соединения закрываются, новые идут через резерв. Уже отправленные запросы не повторяются автоматически, чтобы не дублировать действия в игре. WebSocket и другие постоянные соединения должны переподключиться средствами сайта. Нулевая пауза не гарантируется.
- **Строгая сетевая изоляция**: перед запуском проверяется внешний IP. Если этот IP или VPN-сервер уже закреплён за другим профилем, запуск блокируется с объяснением. Разные локальные порты не считаются отдельными внешними IP.
- **Kill-Switch**: если подходящий VPN-сервер не найден, запуск блокируется, а работающий локальный прокси отклоняет соединения до восстановления проверенного VPN. Он подключается только к числовым loopback-адресам SOCKS-ядра Xray; прямого выхода, локального разрешения имён сайтов, UDP и BIND в этом прокси нет. Существующие ограничения Chrome на QUIC и WebRTC сохраняются. Общий Happ не подставляется вместо настроенного пула.

Для включения автоматического резерва после обновления один раз перезапустите программу и окна ботов. Изменение списка узлов во время работы блокирует прежние шлюзы; после изменения также требуется перезапуск программы. Готовность резерва видна в подсказке VPN аккаунта. При нехватке отдельных серверов/IP резерв может отсутствовать: история изоляции не очищается и чужие маршруты не используются.

Все запускатели используют общую HTTPS-проверку VPN и отдельные каталоги Chrome в `%LOCALAPPDATA%\LegionMultiBot\Bots`. Для ранее использовавшихся обычных профилей Chrome может потребоваться повторная авторизация. Уже открытый профиль нужно закрыть перед сменой его прокси.

Проверка серверов работает через отдельный временный Xray и сохраняет маршруты открытых окон. Не ответившие серверы остаются в списке для повторной проверки. При аварийном завершении рабочего ядра выполняется попытка восстановления; прямой интернет не используется как резерв.

Рабочее и проверочное ядра Xray входят в Windows Job Object до начала выполнения: аварийный выход их запускателя завершает эти процессы. Обычное закрытие программы явно останавливает принадлежащее ей ядро и прекращает его автоматический перезапуск. Запись владельца содержит PID, время создания и путь как ядра, так и запускателя. Оставшееся от старой версии ядро восстанавливается только после проверки точного исполняемого файла, пути конфигурации мультибота, завершения прежнего владельца и отсутствия использующих прокси браузеров. Работающий Happ и ядра с другой конфигурацией не завершаются.

Ключи и ссылка подписки хранятся локально в `.vpn_runtime/vpn_config.json`; каталог исключён из Git. Корневой `vpn_config.json` — пустой шаблон. Если реальные ключи ранее попали в коммиты или передавались вместе с репозиторием, их необходимо заменить у VPN-провайдера: перенос конфигурации не удаляет старые значения из истории Git.

Проверки безопасности: `python -B -m unittest discover -s tests` и `node --test tests/secure_launch.test.js`.

## Мобильные профили и переход со старой версии

По умолчанию используется обычный настольный Chrome. Прежние `mobile_device.json` сохранены для совместимости, но в стандартном режиме не читаются и не создаются. Четыре пресета эмуляции остаются только для явно выбранного программного режима `emulate_mobile=True` и его тестов. Уникальность аппаратного устройства не заявляется. Номер VPN-маршрута закрепляется за аккаунтом в `.network-slots.json`; внешний IP зависит от назначенного сервера и в режиме «С VPN» проверяется перед запуском.

История проверенных IP и VPN-серверов хранится рядом в `.network-isolation.json`, отдельно от программы. Запись защищена межпроцессной блокировкой и сохраняется атомарно: одновременные запуски не могут закрепить один проверенный IP за разными профилями. Привязки сохраняются после закрытия окна и перезапуска; ранее замеченный IP остаётся за своим профилем и после смены адреса. Повреждённая история блокирует запуск и не перезаписывается. VPN-ключи в неё не записываются; идентификатор сервера — хеш протокола, адреса и порта. Без списка узлов общий Happ допускается только для одного профиля.

После обновления закройте старые окна и перезапустите запускатели. Проверка начинает собирать историю с первого запуска новой версии: она не знает прошлые IP и не отменяет уже возникшие связи аккаунтов. Не удаляйте историю, чтобы обходить конфликт: назначьте отдельный VPN-сервер с другим внешним IP. Проверка относится к моменту запуска и IP, который видит проверочный HTTPS-сервис; маршрутизация по назначению, смена адресов во время работы и другие адресные семейства ею не контролируются. Для открытых окон не меняйте VPN-конфигурацию. Профилем здесь считается каталог браузера: вход другим игровым аккаунтом в тот же профиль не создаёт новую изоляцию.

В сетке страница получает настоящий размер окна Chrome. Искусственный масштаб viewport отключён; в панели указана подсказка штатного масштаба Chrome — `Ctrl` + `+` / `−`. Вкладки, адресная строка и рамка Chrome скрываются за границами ячейки: видимая область определяется по нативному окну страницы и пересчитывается при изменении размеров. Размеры и поведение узкого настольного окна отличаются от прежнего фиксированного телефонного кадра.

Оставшийся после завершения старого запускателя Chrome восстанавливается автоматически: проверяются каталог аккаунта, исполняемый файл, время создания процесса и отсутствие живого владельца. Программа закрывает только этот браузер и открывает профиль заново, сохраняя его данные. Если владельцем остаётся другой работающий экземпляр, профиль не перехватывается. Новые браузеры входят в Windows Job Object до начала выполнения: при аварийном завершении запускателя Windows завершает их процессы. При обычном выходе сначала запрашивается штатное закрытие Chrome. «Закрыть всё» также отменяет ожидающие запуски, включая задачи проверки VPN.

Лаунчер запускает Chrome без стартового окна (`--no-startup-window`), подготавливает управление и затем создаёт единственное окно сразу с целевым адресом. Это устраняет подтверждённые нулевые `outerWidth/outerHeight` при прежнем переходе из окна `--app=data:...`. Если включены пользовательские скрипты, ответ документа кратко удерживается до регистрации загрузчика; содержимое, запросы и заголовки не изменяются. Это сохраняет выполнение `document-start` до кода страницы при открытии основного окна. В DevTools Protocol настраиваются только верхнеуровневые страницы; workers не ставятся на паузу. Управление идёт через DevTools WebSocket на случайном ненулевом порту `127.0.0.1`. Перед подключением проверяется PID владельца слушающего порта; подмена другим процессом или привязка ко всем сетевым интерфейсам блокируется. Переадресация управляющего URL запрещена. Дополнительных Python-пакетов не требуется. Повторное открытие игры/2ip использует существующее окно приложения. При переходе из собственного окна настройки/авторизации в сетку браузер аккуратно перезапускается с тем же профилем, сохраняя данные.

Старое расширение Shield отключено: его совместимый manifest больше не содержит content scripts. В существующих профилях выполняется точечное удаление `__lg_mobile_shield_device` при создании документа в изолированном контексте. Другие ключи, cookies, IndexedDB и авторизация не очищаются. Новые профили не получают служебные записи в хранилище сайта. После закрытия приложения управляемые браузеры закрываются вместе с каналом управления.

Перед запуском закрытого профиля задаётся штатная настройка Chrome `webrtc.ip_handling_policy = disable_non_proxied_udp`. Исходный Preferences сохраняется в `preferences-before-network-privacy.json` внутри того же профиля; остальные настройки сохраняются. Повреждённый Preferences не перезаписывается. Политика не внедряет JavaScript-обёртки в страницу. Это дополняет параметры прокси и запрет прямого резервного соединения.

Предварительная загрузка сети отключена настройкой `net.network_prediction_options = 2` и параметром `--dns-prefetch-disable`. Целевые имена передаются SOCKS5/HTTP-прокси штатным механизмом Chrome. Параметр `--host-resolver-rules` удалён: в текущем Chrome он вызывает предупреждение о неподдерживаемом флаге. Предупреждения браузера программно не скрываются.

## Скрипт из GitHub для всех окон

При новой установке LegionAutoMiner уже включён по умолчанию со ссылкой на `mine-bot.user.js` из https://github.com/Daniil0414/LegionAutoMiner. Перед первым открытием игрового окна мультибот автоматически скачивает и устанавливает скрипт; все следующие окна получают его автоматически. Вручную добавлять или включать скрипт не требуется. Для первой загрузки нужен доступ к GitHub; при ошибке окно не открывается, следующая попытка запуска повторяет загрузку. Скачанная версия сохраняется для работы при недоступности GitHub. Ручное отключение скрипта и существующие списки сохраняются.

В приложении нажмите «🤖 Скрипт бота», вставьте ссылку на файл GitHub (`.../blob/main/bot.user.js` или `raw.githubusercontent.com/...`) и нажмите «Добавить скрипт во все окна». Чтобы установить второй и следующие скрипты, нажмите «＋ Добавить ещё» и вставьте новую ссылку. Выбор существующего скрипта позволяет обновить его ссылку или отключить только его; повторная установка включает его обратно. В веб-менеджере те же настройки находятся под адресом игры. Установка общая для всех профилей и сохраняется между запусками приложения.

Перед каждым запуском профиля мультибот заново запрашивает каждый включённый скрипт с GitHub, сохраняет настройки атомарно и регистрирует скрипты в Chrome до перехода на страницу игры. Скрипты с одинаковым `@run-at` выполняются в порядке добавления; правила адресов и времени запуска применяются отдельно к каждому. Новые окна и перезагрузки получают скрипт автоматически. Когда код меняется, уже открытые управляемые окна перезагружаются. Кнопка «Отключить выбранный скрипт» убирает только выбранный скрипт и перезагружает окна. Расширения в управляемом Chrome отключены, Tampermonkey устанавливать не требуется.

При недоступности GitHub или некорректном обновлении используется последняя сохранённая версия; интерфейс показывает ошибку обновления. Если сохранённая версия повреждена или отсутствует, запуск блокируется. Неудачная установка новой ссылки сохраняет предыдущий скрипт. Статус, версия, время обновления и резервная копия независимы для каждого скрипта. Прежняя настройка одного скрипта переносится в список автоматически, с сохранением кода и состояния включения.

Поддерживаются обычные JavaScript-файлы и userscript с `@grant none`, `@match`, `@include`, `@exclude`, `@exclude-match`, `@noframes`, `@run-at document-start/document-end/document-idle`. Скрипт выполняется только на соответствующих HTTP/HTTPS-страницах. GM API, `@require`, `@resource` и регулярные выражения в `@include/@exclude` не поддерживаются; такие метаданные отклоняются при установке.

Для LegionAutoMiner с `@namespace https://github.com/Daniil0414/LegionAutoMiner` автоматически применяется адаптация приватного состояния. Она требует установленного Node.js; JavaScript разбирается встроенным Acorn 8.19.0, лицензия находится в `vendor/acorn.LICENSE`. Обращения к служебным `__mine*`/`__lg*` на `window` и флаги вроде `__botHooked` на игровых объектах перенесены в замыкание с WeakMap. Исходник на GitHub и сохранённая исходная версия не переписываются. Обычные сторонние скрипты сохраняют прежнее поведение. Если обновление известного бота утрачивает поддерживаемый формат, используется проверяемая сохранённая версия, а не тихое отключение режима.

Настройки `lg_bot_*`, `lg_quest_*`, `lg_unlocked_sk_*` и перечисленные в `userscript_privacy.py` служебные значения хранятся в `userscript-private.json` внутри отдельного каталога профиля, с разделением по origin. Старые значения удаляются из localStorage игры только после подтверждённой записи файла; cookies, авторизация и прочие ключи не удаляются. Повреждённый файл останавливает запуск самого скрипта, сохраняя старые значения. При первой миграции старые ключи могут оставаться видимыми до подтверждения записи. Изменения сохраняются асинхронно; аварийное завершение до подтверждения может потерять последнее изменение настройки.

Панель бота, подсказки, всплывающие сообщения и быстрый HUD размещаются в закрытом Shadow DOM. Их ID и текст недоступны обычному `document.querySelector` страницы; сам элемент-контейнер, визуальное отображение, события и изменения игры остаются наблюдаемыми. Служебное изменение заголовка вкладки остаётся внутри состояния бота. Обмен настройками проходит через именованный изолированный контекст Chrome; функции доступа к файлу не публикуются в `window` страницы, подписка `Runtime.enable` не включается. Это уменьшает конкретные признаки, но не создаёт полной границы безопасности для кода бота, работающего в контексте игры.

## Локальный веб-менеджер и передача программы

Веб-менеджер слушает только `127.0.0.1`, использует случайный порт и одноразовый ключ доступа. Cross-origin запросы и произвольные Host отклоняются; CORS `*` удалён. Открывайте адрес из текущего запуска; ключ хранится в sessionStorage самого менеджера. Настройка фиксированного порта возможна через `LEGION_MANAGER_PORT`. Наличие локального сервиса не объявляется неотслеживаемым.

Для передачи программы используйте `python -B package_app.py`. Архив `dist/legion-multibot.zip` создаётся по явному списку исходников и содержит пустой шаблон VPN. Профили браузера, accounts.json, ссылки на скрипты, VPN-ключи, логи, `.git` и сторонние расширения в него не входят. Архив не является инсталлятором: на целевой Windows нужны Python 3.10+ с Tk, Chrome, Happ/Xray и Node.js для веб-менеджера.

## Проверки и ограничения

Обычные проверки: `python -B -m unittest discover -s tests` и `node --test tests/*.test.js`.

Интеграционные проверки Chrome в PowerShell:

```powershell
$env:LEGION_TEST_CHROME = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
python -B -m unittest discover -s tests
```

Тесты создают временные профили и локальный HTTP-прокси, не входят в игру и не используют существующие аккаунты. Проверяются первый запрос, согласованность JS и HTTP Client Hints, мобильный экран, iframe, dedicated/shared/service workers, новые окна, WebSocket, сохранение данных при миграции, изоляция профилей и отсутствие прямого подключения при отказе прокси. Дополнительно проверяются передача неразрешимого имени через прокси и локальное ICE-согласование без STUN: без непроксируемых UDP-кандидатов. IPv6-loopback проверяется только при доступности контрольного подключения в ОС.

`tests/test_native_browser.py` сравнивает стандартный запуск с обычным Chrome без отладочного подключения: `webdriver`, экран, DPR и размеры окна, сенсорный ввод, указатель, Client Hints и HTTP-заголовки, плагины, глобальные свойства страницы, нативность выбранных функций и чтение `Error.stack` при выводе в консоль. На локальном стенде эти проверки совпадают. Эмуляция телефона тестируется отдельно и включается в тестах явно.

Аппаратные параметры и поведение сетевого стека могут оставаться общими. Настройки установленных расширений, внешние игровые проверки, серверные корреляции аккаунтов и все варианты фонового трафика не покрываются этими тестами. Совпадение проверенных сигналов с обычным Chrome не означает гарантии нераспознаваемости или отсутствия банов. Полный интерфейс авторизованной игры требует отдельной проверки после перезапуска.

В Chrome 156.0.8078.74 прежний запуск через `--remote-debugging-pipe` давал `navigator.webdriver === true`. Новый запуск с ненулевым loopback-портом, без headless и `--enable-automation`, возвращает `false`: проверены первая загрузка страницы, iframe и новое окно. JavaScript-getter не заменяется и остаётся нативным. Headless-режим интеграционных тестов по-прежнему может сообщать об автоматизации. Это устранение одного подтверждённого признака, а не гарантия нераспознаваемости.

Локальный DevTools-порт доступен программам на этом компьютере; транспорт не имеет собственной аутентификации. Проверено, что Chrome отклоняет WebSocket-подключение с посторонним веб-Origin и не выдаёт CORS-разрешение `*` для метаданных. Параметр `--remote-allow-origins=*` не используется. Наличие локального порта и другие способы обнаружения DevTools не исключены.

Загрузчик userscript не добавляет `Symbol.for('legion.userscript')` в объект страницы. Защита от повторного выполнения использует непредсказуемое имя события, замкнутое в загрузчике. Сам пользовательский скрипт может создавать глобальные переменные, интерфейс и другие наблюдаемые признаки; их отсутствие не обещается.

В исходнике `mine-bot.user.js` остаются имена `__mineBotRunning`, `__lgMineS`, `mine-bot-v3` и `lg_bot_*`: адаптация применяется загрузчиком перед выполнением, а не обфускацией исходника. Она проверена на локальной странице с полным установленным скриптом: служебные глобальные свойства, перечисленные DOM-ID и ключи `lg_bot_*`/`lg_quest_*` через обычные API страницы не обнаружены, панель инициализируется. Сам бот по-прежнему изменяет функции игры и браузера, выполняет действия и запросы; их последствия, анализ кода приложения и серверные связи аккаунтов эта адаптация не скрывает. Полный игровой цикл с авторизованным аккаунтом не проверялся. Необнаружимость мультибота и невозможность связать твинки не гарантируются.
